# Repository validation

The repository follows the pinned Bonsai Foundation Prefect reference tree. Run `pwsh build/validate-prefect.ps1` to obtain Prefect and validate it.

The validation script prepares a reference copy with explicit content exceptions. `.github/workflows/Bonsai.Http.yml` runs Framework tests on Windows and .NET 8 transport tests on Windows/Linux/macOS instead of the reference's unsupported framework matrix. `docs/build.ps1` excludes test output directories from renderer library inputs so the Windows test host is not loaded by Bonsai. `docs/export-images.ps1` uses the same public Bonsai WorkflowExporter API in a modern .NET host for the modern-only server example; the other workflows use the shared template renderer. `docs/articles/toc.yml` and `docs/template/public/main.js` contain the package's guide navigation and repository link. The site uses the standard Bonsai documentation styles without additional styling. Structural checks and all other Prefect rules remain enabled. The generated API sample uses the conventional `Extensions.csproj` project recognized by Prefect for workflow extensions.

`SPEC.md` is an ignored local planning document and must never be staged or committed.

To build and serve the documentation at `http://localhost:8090`, run `pwsh docs/serve.ps1`. It restores DocFX, generates the API reference, and builds the site with documentation warnings treated as errors. Use `-NoBuild` to serve an existing build or `-Port 8091` to choose another port. Guides embed source files from `docs/workflows` using the shared `:::workflow` widget. The standard `docs/build.ps1` calls `docs/export-images.ps1` to render their SVGs automatically before DocFX builds the site. Generated SVGs are ignored by Git. Build the runtime libraries and the generated OpenAPI extension first; `docs/serve.ps1` performs these steps for a preview.
